## Что такое стиль

Стиль — набор правил движения, который одинаково применяется к любому экрану. Это папка `<id>/`:

| Файл | Что в нём |
|---|---|
| `passport.md` | Паспорт для людей: характер, когда подходит, референсы, изменения вида, роли с источниками и лицензиями, reduced motion. Из него собирается `motion-spec.md` |
| `tokens.json` | Токены: длительности, кривые, пружины, каскад, сдвиг, размытие ([runtime.md](runtime.md), «Токены») |
| `style.tsx` | Код: объект `MotionStyle` с реализациями ролей и вариантов |
| `style.css` | Необязательно. Свои CSS-правила с префиксом стиля |

- **Коллекция** `design/motion/styles/<id>/` открытая, стартового набора у неё нет. Выбранный стиль попадает в неё при фиксации и может пригодиться следующему продукту.
- **В продукте** макет загружает только стили из `<продукт>/mockup/src/motion/styles/*/style.tsx`.
- **id** = имя папки = поле `id` в `style.tsx`. Если они не совпадают, реестр падает при загрузке и макет не открывается. Строчная латиница, цифры, дефис (`calm-glass`): такой id подходит и для `use`, и для CSS-префикса.

## Как собрать кандидатов (шаги 1–6)

Инструменты Screenrove подключены как MCP `screenrove`. Схемы инструментов загружаются через ToolSearch: `select:mcp__screenrove__search_motion,mcp__screenrove__get_motion,…`.

### 1. Характер продукта

Берётся из брифа (продукт, аудитория, слова настроения) и из экранов-референсов.

- `mcp__screenrove__search_screens` — поиск экранов. Параметры:
  - `q` — слова, в том числе про вид: «dark», «editorial», «gradient», «pricing page»;
  - фильтры по тегам: `pattern`, `task`, `component`, `state`. Словарь тегов даёт `list_tags`;
  - `product`, `kind` (`flow` | `marketing` | `product`);
  - `fields: "brief"` — по строке на экран; `limit`, `offset` — страницы.
- У каждого экрана есть `style`: `theme`, `aesthetic`, `density`, `colorMode`, `accentHue`, `headingFont`, `imagery`, `caption`. Из них и складывается характер. Для цитирования там же лежат `url` и дата `captured`.
- Посмотреть до решения:
  - `mcp__screenrove__get_screen_image({ screenId })` — картинка 1x;
  - или `mcp__screenrove__build_recipe({ screens: ["<id>: что взять", …] })` — 2–6 экранов с картинками и замерами. Для интерактивных частей рецепт сам предлагает подходящие записи движения.
- «Как у <продукт>» — `mcp__screenrove__get_design({ productId })`: шрифты, палитра, плотность.
- Если пользователь рядом и хочет выбрать сам: `mcp__screenrove__pick_reference` открывает выбор в браузере, `mcp__screenrove__wait_for_pick({ pickId })` ждёт ответ.
- Называть можно только продукты, которые вернул Screenrove. Каталог неполный.

Итог шага — характер в 2–3 строки. Пример: «Финансы команды, спокойная уверенность. Экраны светлые, плотность средняя, один акцент, без декора».

### 2. Снять движение с референсов

Анимации не выдумываются: каждый кандидат строится на движении, снятом с реального референса. Снимать нужно **один раз**, при подборе кандидатов для 1–2 ключевых экранов (входы 1, 2 и 3 при `style: null`). Новый экран при выбранном стиле (вход 4) не снимает и кандидатов не показывает: роль берётся из выбранного стиля, а если её у стиля нет, дописывается в характере стиля. Если у референса выбранного стиля эта роль есть в `record.md`, параметры берутся оттуда.

**Источники:**

| Источник | Как получить адрес |
|---|---|
| Сайты, которые назвал пользователь | Адрес берётся как есть |
| Экраны-референсы из `search_screens` (шаг 1) | `mcp__screenrove__get_screen({ screenId })` → поле `source` (адрес живой страницы). Если `scope` равен `signed-in`, экран **не снимается**: он за входом в аккаунт |
| Записи библиотеки Screenrove | `search_motion` и `get_motion` (шаг 3), как раньше. Это готовая запись движения, снимать её не нужно |

Снимаются только публичные страницы: без входа в аккаунт и без кликов, которые меняют данные.

**Команда** (из корня репозитория):

```bash
node design/motion/scripts/capture-motion.mjs <url>
```

- Дополнительно: `--out <папка>`, `--phases load,scroll,hover,focus`, `--viewport 1440x900`.
- Результат — `design/motion/captures/<slug>/`: `record.md` (читать его), `capture.json`, `media/frames/*.png` и `media/video.webm` (медиа в git не попадает). `slug` — хост без `www.` и путь: `mercury.com`, `ramp.com-pricing`.
- Один сайт занимает около 45 секунд: запускается браузер и пишется видео. Сайты снимать **по одному**, друг за другом. Если в сессии есть другая работа, запускать в фоне (`run_in_background`).
- **Свежая запись** — снята не позже 30 дней назад (дата в шапке `record.md` или `capturedAt` в `capture.json`). Свежую повторно не снимать. Старую снять заново.

**Как читать `record.md`:**

| Раздел | Что взять |
|---|---|
| `## Сигнатурные приёмы` | До 5 самых заметных приёмов. Каскад свёрнут в одну строку («× N элементов, каскад X мс»). Фоновые петли сюда не входят намеренно. Отсюда выбирается идея кандидата |
| `## По фазам` | Таблицы «Загрузка», «Прокрутка», «Наведение», «Фокус»: элемент, что движется, откуда → куда, длительность, кривая или пружина, задержка, основа |
| Строки «привязано к прокрутке: N px за M px прокрутки» | Параллакс или scrub: движение идёт за прокруткой, а не по времени. Длительности и кривой нет, в токены не входит. Повторять привязкой к прокрутке (`useScroll` + `useTransform` в Motion) с тем же отношением N / M, а не анимацией по времени |
| Строки «каскад 80 мс × 4: …» | Шаг каскада и число элементов |
| Строка «Фоновые петли» под таблицей | Счётчики (number-flow), тикеры, Lottie: петли, найденные по повторам, и JS-движение, которое ещё идёт в конце фазы. Не реакция. В приёмы и токены не входят. Бесконечные CSS/WAAPI-анимации (бегущие строки, пульс) сюда не попадают: они в таблицах фаз, с пометкой «бесконечно» |
| Строка «Смена цвета» под таблицей | Цвет текста, фона, рамки (тема шапки при прокрутке и т. п.): не стиль движения. Длительность и кривую можно взять для смены темы |
| `## Черновик токенов` | Блок `json` в формате `tokens.json`. Отправная точка, а не готовые токены |
| `## Пропущено` | Что было на странице, но в таблицы не попало: видео и canvas с размером (их движение — только на кадрах и видео); скачки без анимации и записи длительностью 0 мс; движение по замеру, что вернулось к началу; короткие переходы, которые закончились до замера; фоновые повторы; элементы, на которые не удалось навести. Большое видео или canvas здесь — повод открыть кадры |
| `## Ограничения` | Что инструмент не снимает в принципе; текст одинаковый во всех записях, поэтому есть ли такое на этом сайте, смотреть кадры. Сюда относятся: canvas и WebGL (в том числе Lottie на canvas), видео, морфинг SVG-путей, CSS-переменные, которые меняются из JS на предке, анимации на scroll-timeline. Движение по клику (вкладки, аккордеоны, модальные окна) не снимается совсем: съёмка не кликает. Такое видно только на кадрах и видео в `media/` (клик — только если открыть сайт самому); воспроизводится «на глаз», основа «видео» |
| `## Лицензия` | Движение — образец. Код, тексты и картинки сайта не копируются |

Столбец «Основа»: `точно (CSS)` и `точно (WAAPI)` — числа из кода страницы, переносить как есть; `замер` — приблизительно, измерено по кадрам (допустимо округлить до ближайших 10 мс).

**Пустая или бедная запись.** Сначала открыть кадры `media/frames/*.png` (Read). Если на них есть движение, которого нет в таблицах (объёмный объект, свет, атмосфера на canvas или WebGL), запись не бедная: кандидат строится на ней «на глаз», основа «видео». Если и на кадрах движения почти нет, или в «Сигнатурных приёмах» только «появление снизу с растворением» и каскад, идеи для кандидата нет. Сказать об этом пользователю («<домен>: движения почти нет, беру другой референс») и снять другой сайт. Такая запись кандидата не даёт. После двух бедных записей подряд опереться на запись библиотеки Screenrove (шаг 3) или попросить у пользователя сайт.

### 3. Поиск движения по характеру

- Правила по умолчанию — снимок `get_motion_guidelines` на 31.10.2026 с ключевыми числами в [sources.md](sources.md). Обычно хватает его. Сам инструмент `mcp__screenrove__get_motion_guidelines` вызывать, если стиль отступает от правил или числа нужно перепроверить.
- `mcp__screenrove__search_motion`:
  - `q` — слова характера и приёма: «tactile», «spring», «blur», «liquid glass», «shimmer», «press», «stagger», «otp». Чем больше слов совпало, тем выше запись;
  - `category` (через запятую, ИЛИ): `button`, `toggle`, `input`, `list`, `card`, `navigation`, `overlay`, `toast`, `loader`, `text`, `number`, `chat-ai`, `cursor`, `scroll`, `transition`, `icon`, `feedback`, `media`, `sound`, `other`;
  - `trigger`: `hover`, `press`, `click`, `focus`, `load`, `scroll`, `drag`, `state-change`, `loop`, `type`;
  - `basis`: `code` (точные числа из исходника), `video` (замер по записи), `rebuild`;
  - `hasCode: true` — только записи с рабочим кодом; `source` — id источников;
  - `limit` держать 5–8: сокращённого вывода у `search_motion` нет, каждая запись приходит с описанием и тегами (`fields: "brief"` есть только у `search_screens`).
  - Для OTP: `q: "otp"`, `category: "input,feedback"` (`feedback` — успех и ошибка).
  - В ответе у записи: `id`, `summary`, `category`, `triggers`, `source { id, name, license }`, `credit` (у записей дизайнеров), `basis`, `url` (страница записи), `demoUrl`, иногда `videoUrl`.
- `mcp__screenrove__get_motion({ motionId, code })` выдаёт:
  - таблицу «что движется, откуда куда, длительность, кривая или пружина, задержка, когда»;
  - пружины в виде CSS;
  - поведение при reduced motion и доступность;
  - что сохранить при пересборке;
  - источник с лицензией и ссылку на демо.

  Сначала звать с `code: "none"` — только спецификация, меньше текста. Для выбранных записей — `code: "original"` (если лицензия позволяет) или `"vanilla"`. Тайминги сохранять, расстояния масштабировать под свой элемент.
- Сайты пользователя и экраны-референсы снимаются командой из шага 2; видео и приложения, демо-страницы библиотек и каталог 21st.dev → [sources.md](sources.md).
- **У референса нет нужной роли** — только для такой роли её можно реализовать самому по правилам движения, в характере стиля. Это видно в паспорте: если опирались на запись дизайнера, «Источник» — её id, «Лицензия» — «своя реализация (образец: <id записи>)»; если опереться не на что — «Источник» «без референса», «Лицензия» «своя реализация».

Категории Screenrove примерно ложатся на роли так:

| Категория | Роль |
|---|---|
| `button` | `button` |
| `navigation` | `nav-link` |
| `card` | `card` |
| `input` | `input`, `otp` |
| `toggle` | `toggle` |
| `overlay` | `overlay` |
| `toast` | `toast` |
| `number` | `number` |
| `list` | `list` |
| `loader` | `loading` |
| `text`; записи с триггером `load` | `screen-enter` |
| `transition` | `screen-transition` |
| `scroll`, `cursor`; фоновые записи с триггером `loop` | `ambient` — только там, где это уместно по паспорту |

### 4. Сборка кандидата

Из снятых записей, записей Screenrove и компонентов библиотек собирается паспорт кандидата (ниже): токены, поведение по ролям, изменения вида, ссылки на референсы.

**Анимации не выдумываются.** Каждый кандидат стоит на **одном** снятом референсе (или одной записи Screenrove) и повторяет его движение: те же длительности, кривые или пружины, форму ключевых кадров и каскад. Сдвиги масштабируются под размер своего элемента. Правило «разные идеи» остаётся главным: несколько вариантов — это кандидаты из **разных** референсов с **разными** идеями, а не копия всего подряд, что есть у референса.

Роли ищутся в записи так:

| Что на экране | Роль | Где в `record.md` |
|---|---|---|
| Заголовки и блоки первого экрана | `screen-enter` | «Загрузка» |
| Кнопки | `button` | «Наведение» |
| Ссылки меню | `nav-link` | «Наведение» |
| Карточки | `card` | «Наведение», «Прокрутка» |
| Поля | `input` | «Фокус» |
| Счётчики | `number` | Обычно строка «Фоновые петли» (number-flow: CSS-переменные `--_number-flow-*`) в «Загрузке» и «Прокрутке»; одиночный счёт до числа — в таблицах тех же фаз |
| Фон | `ambient` | Строки с пометкой «бесконечно» в таблицах фаз и в «Сигнатурных приёмах» (бегущие строки, пульс, спиннер). Петли по повторам и JS-движение в конце фазы — строка «Фоновые петли», а также «Пропущено» (видео, canvas с размером), кадры и видео |
| Параллакс, scrub (строки «привязано к прокрутке») | `ambient` (привязка к прокрутке) | «Прокрутка». Это не `screen-enter`: длительности у такого движения нет |

- «Черновик токенов» из записи — отправная точка `tokens.json` кандидата. Числа в нём сверить с таблицами фаз; единицы те же, что в `tokens.json`: длительности и каскад в мс, сдвиги и размытие в px.
- Приём, снятый только на кадрах и видео (canvas, WebGL, морфинг), воспроизводится «на глаз»; в паспорте основа «видео» пишется в «Параметрах» как «(основа: видео)».
- Роль, которой у референса нет, остаётся «Без анимации» или делается самостоятельно по правилам движения («своя реализация», шаг 3, последний пункт).

**Перед показом пользователю** посмотреть кадры каждого кандидата самому: headless-скриншоты в несколько моментов (0, ~0,5, ~1, ~2 с и покой) и честно оценить, читается ли фирменный момент и отличаются ли кандидаты друг от друга. Не читается — доработать или заменить, не показывать.

Кандидат — всегда полноценный стиль, даже если спросили про одно место: это первый шаг к выбору стиля продукта. Но реализуются только роли, которые есть на экранах, собираемых сейчас. Это и есть минимум работы. Остальные роли — «Без анимации», их дописывают позже, когда они встретятся на новом экране.

### 5. Переиспользование

Шаг выполняется, только если в коллекции есть подходящие стили. Пока там может лежать одна `_template` (заготовка, не стиль) — тогда шаг пропускается.

Посмотреть коллекцию: `ls design/motion/styles`. У каждого стиля прочитать «Характер» и «Когда подходит» в `passport.md`. Подходящий этому продукту стиль идёт в кандидаты наравне с новыми как есть (правило одного референса — для новых кандидатов):

```bash
node design/motion/scripts/add-style.mjs <продукт> <id>
```

### 6. Объяснение

Для каждого кандидата — одна-две фразы, почему он подходит именно этому продукту, и ссылки на референсы: страница записи Screenrove (`url`) и демо (`demoUrl`), страницы библиотек, снятый сайт и его `record.md`. То же — в разделах паспорта «Когда подходит» и «Референсы», а ссылки — в `references` в `style.tsx`, чтобы панель макета их показала. Снятый сайт идёт туда как `kind: 'site'`; `record.md` — локальный путь, в панели он был бы битой ссылкой, поэтому только в паспорт.

## Правила набора

Правила идут по приоритету: сначала «подходит продукту», потом «своя идея», потом оси.

- **2–3 кандидата.**
- **Каждый кандидат стоит на одном снятом референсе** (или записи Screenrove) и повторяет его движение (шаг 4). Референс без идеи («бедная запись», шаг 2) кандидата не даёт. Разные кандидаты — разные референсы и разные идеи.
- **1. Каждый кандидат подходит продукту.** Например, стиль с бегущими лучами и подсветкой хорош для лендингов и AI-продуктов и плох для рабочих инструментов, которыми пользуются весь день. Неподходящий стиль не берут ради разнообразия.
- **2. У каждого кандидата своя идея.** Кандидат строится вокруг собственного фирменного приёма: что именно движется (типографика и маски, объекты в 3D, свет и атмосфера, хореография фигур, визуализация данных и т. п.). Приём виден в первые ~2 секунды первого экрана. Варианты одной идеи (другие длительности, пружины, сдвиги) разными кандидатами не считаются.
  - **Антипаттерн:** «появиться снизу с растворением каскадом» — это фон, а не идея стиля. Кандидат, у которого только оно, кандидатом не является. Пользователь видит «ну появилось и появилось», «сложно найти различия», «шаблонная анимация».
  - **Лимиты Screenrove** (100–300 мс, малые сдвиги) относятся к микровзаимодействиям интерфейса. Входное и фоновое движение лендинга или первого экрана может быть смелее и длиннее; отступление записывается в паспорт.
  - **Перед сборкой** записать для набора короткую таблицу и проверить, что человек отличит кандидатов по двухсекундному взгляду:

    | Кандидат | Идея | Фирменный момент | Изменения в покое |
    |---|---|---|---|

- **3. Оси — вторичная проверка.** Попарно различаются минимум по двум осям из трёх. Сильные эффекты — только если характер продукта их допускает. Если два кандидата совпали по двум осям, поменять одного.

  | Ось | Чем задаётся |
  |---|---|
  | Темп | `duration.*`, `stagger` |
  | Упругость | пружины с перелётом (`spring.*`, низкий `damping`) против плавных кривых (`ease.*`) без перелёта |
  | Сила эффектов | `distance`, `blur`, масштаб, декоративные слои (луч, подсветка, конфетти), изменения вида в покое |

- **Кривые выхода** — по правилу Screenrove: выход тоже на сильном ease-out (не ease-in) и быстрее входа.
- **Хотя бы у одного кандидата «Изменения вида в покое» = «Нет»**, чтобы пользователь мог сравнить с «чистым» макетом из pen.dev.
- **Постоянной тройки нет.** Три стиля из наброска `design/motion/sketches/screen-styles.html` (сдержанный, пружинный, эффектный) — только пример формата.

## Новый стиль из заготовки

```bash
cp -r design/motion/styles/_template <продукт>/mockup/src/motion/styles/<id>
```

Затем заполнить:

- **`style.tsx`**:
  - `id: '<id>'`, `name`, `tagline`;
  - `restingChanges` — те же пункты, что в паспорте;
  - `references` — `{ title, url, kind }`, где `kind` — `screenrove-motion` | `screenrove-screen` | `library` | `site` | `video`;
  - `roles`, при необходимости `variants`.

  Панель макета показывает `name`, `tagline`, `restingChanges` и `references`, поэтому держи их в согласии с паспортом. API ролей — в [runtime.md](runtime.md). Готовый пример — `design/motion/template/src/motion/styles/fixture-b/`.
- **`tokens.json`** — все поля, лишних нет: lint ругается и на пропуски, и на лишнее.
- **`style.css`** — каждый селектор начинается с `[data-motion-style="<id>"]`, в том числе внутри `@media` и `@supports`.
  - Reduced пишется как `[data-motion-style="<id>"][data-motion-reduced] …` и `[data-motion-style="<id>"]:not([data-motion-reduced]) …`.
  - Правила доходят и до порталов: атрибуты стоят и на `<html>`.
  - Подробнее — [runtime.md](runtime.md), «Стиль» и «Reduced motion».
  - Если свои правила не нужны, удалить файл вместе с импортом в `style.tsx`.
- **`passport.md`** — раздел «Паспорт» ниже.
- Вписать `<id>` в `candidates` в `motion.json`.

## Паспорт

Заголовки — ровно такие, `lint-style` ищет их по тексту:

```markdown
# <Название стиля>
## Характер
## Когда подходит
## Референсы
## Изменения вида в покое
## Роли
## Источники и установка
## Reduced motion
```

- **Характер** — 2–3 предложения: как стиль двигается и что чувствует пользователь. Здесь же отдельной строкой отступления от правил Screenrove: «Отступление от правил Screenrove: …, потому что …». `motion-spec` переносит этот раздел в спецификацию.
- **Когда подходит** — тип продукта, аудитория, слова настроения; где стиль не подходит. Если роль `ambient` ветвится по `element` (имена слоёв продукта), здесь прямо написано, что стиль привязан к этому продукту ([runtime.md](runtime.md), «Стиль»).
- **Референсы** — минимум одна ссылка вида `[текст](url)`: записи Screenrove, компоненты библиотек, сайты и видео пользователя. Записи дизайнеров — с именем автора. Для снятого сайта — ссылка на сам сайт и на запись `design/motion/captures/<slug>/record.md`.
- **Изменения вида в покое** — закрытый список того, что стиль меняет относительно pen.dev, например «главная кнопка — градиент акцентных цветов». Если ничего — одна строка «Нет». Всё, чего нет в списке, выглядит ровно как в макете.
- **Роли** — таблица `| Роль | Поведение | Параметры | Источник | Лицензия |`:
  - по строке на каждую из 14 ролей, id в обратных кавычках: `` `button` ``;
  - «Без анимации» в «Поведении» — допустимо, лицензию тогда можно не писать. В остальных строках лицензия обязательна;
  - строки вариантов — `` `otp/<вариант>` `` (вариант: строчные латинские, цифры, дефис);
  - повторов быть не должно;
  - «Параметры» — точные числа, совпадающие с `tokens.json` и кодом;
  - для приёма, снятого с сайта: в «Источнике» — «снято с <домен>», в «Лицензии» — «своя реализация (образец: <домен>)».
- **Источники и установка** — команды установки (`npm install motion`, `npx shadcn@latest add @magicui/border-beam`) и откуда взят каждый приём. Раздел целиком уходит в спецификацию.
- **Reduced motion** — что делает каждая роль при `prefers-reduced-motion`. Появление экрана движок делает мгновенным сам.

Подсказки `<!-- … -->` из заготовки удалить, текст-заглушки заменить своим.

Пример строк таблицы:

```markdown
| `button` | Нажатие сжимает кнопку | scale 0.97, `duration.fast` 150 мс, `ease.enter` | Правила Screenrove (Emil Kowalski) | своя реализация |
| `otp` | Цифра поднимается из размытия, ошибка — одна тряска | 220 мс, сдвиг 10 px, blur 6 px; тряска 320 мс | Screenrove `interior-otp-input` (interior.dev) | MIT |
| `otp/beam` | Луч бежит вокруг активной ячейки | оборот 1,6 с | Magic UI Border Beam | MIT |
| `card` | Карточка приподнимается при наведении | 180 мс, сдвиг −4 px, `ease.enter` | снято с mercury.com | своя реализация (образец: mercury.com) |
| `toast` | Без анимации | | | |
```

## Проверка `lint-style`

```bash
node design/motion/scripts/lint-style.mjs <папка стиля>
```

- Печатает `Проблем нет` или список проблем (код выхода 1).
- Проверяет:
  - наличие `passport.md`, `tokens.json`, `style.tsx`;
  - заголовок и все разделы паспорта; пустой раздел — ошибка;
  - ссылку в «Референсах»;
  - таблицу «Роли»: все роли, неизвестные роли, повторы, лицензию;
  - форму `tokens.json`;
  - префикс селекторов в `style.css`.
- `style.tsx` lint не компилирует. Код проверяют `npx vitest run`, `npm run build` или `npm run dev` в макете.
