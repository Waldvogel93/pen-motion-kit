## Ловушки Pencil MCP

Проверено на pen.dev в октябре 2026. Главное:

- `.pen` зашифрован. Читать и писать только инструментами Pencil MCP, никогда Read или Grep.
- Серверов два:
  - `pencil` — расширение VS Code, основной путь, инструменты `mcp__pencil__*`;
  - `pencil-desktop` — Desktop Pen, только у него есть `browser`.
- **Файл должен быть открыт во вкладке**: `code -r "design/<продукт>.pen"`. С неоткрытым файлом `execute` молча работает с активной вкладкой: чтение вернёт чужие данные, запись уйдёт не туда. Перед записью сверь рамки верхнего уровня.
- Макет лежит прямо в `design/`. Из подпапки он не видит киты в `design/libraries/`.
- Библиотеку кита подключает только пользователь. После этого компоненты и переменные видны с префиксом псевдонима: `H:OyRp5`, `H:--primary`. В `descendants` префикс нужен на каждом сегменте пути.
- `get_app_state` на макете с китами огромный: он перечисляет все компоненты всех библиотек. Вместо него — `execute` с `Get`.
- Обход визитором всего документа (`Get(n => …)`) на файлах с экземплярами из библиотек падает. Рабочий приём:
  - верхний уровень — визитором с `skipChildren`;
  - поддерево — `Get(id, {depth})`, дальше обход в JS.
- Справка по `execute` — `mcp__pencil__read_skill({ path: "execute.md" })`. Упавший вызов исправляют через `edits` с `editId` из ответа, а не повтором.
- Правки библиотеки доходят до макета только после того, как его вкладку закрыли и открыли заново.

## Имена в pen.dev

- **Рамка верхнего уровня — экран.** Id экрана в живом макете (`ScreenDef.id`, маршрут `#/<id>`) совпадает с **именем** рамки. Узловой id в `.pen` (`nCztB`) — это другое.
- **Состояние** называется «Экран / состояние», например `Login / error`. Как его собрать и сверить — раздел «Нарисованные состояния». В имени PNG `/` заменяется на `--`: `Login--error.png`.
- **Префикс `_` — черновик.** В живой макет не собирается и для сверки не выгружается. Экраны макета с `_` (доски вариантов) не попадают в итоговую сборку после фиксации.
- **Имена слоёв** — это `element` у обёрток `R.*` и в `overrides`. Если у подвижного слоя безликое имя (`Frame 12`), предложить пользователю переименовать его до привязки: переименование потом ломает точечные правки (панель предупредит).

## Нарисованные состояния

Рамка `Экран / состояние` (например `Settings / confirm` — Settings с открытым диалогом подтверждения) показывает, как экран выглядит в этом состоянии.

- **В React это состояние того же экрана.** Компонент экрана получает проп (например `confirmOpen`) или держит `useState`. Роли получают `state` и `active`. Отдельный компонент с копией разметки не нужен.
- **Для сверки** зарегистрировать отдельный экран. Его `id` равен имени рамки, а рисует он основной экран в этом состоянии:
  ```tsx
  // src/screens/Settings.tsx — рядом с основным экраном
  export function SettingsConfirm() {
    return <Settings confirmOpen />
  }

  // src/screens/index.ts (это .ts, поэтому без JSX — только импорт)
  { id: 'Settings / confirm', title: 'Настройки — подтверждение', component: SettingsConfirm }
  ```
  Затем сверка с `compare/pen/Settings--confirm.png`:
  ```bash
  npm run compare -- "Settings / confirm" compare/pen/Settings--confirm.png
  ```
- Если состояние не нарисовано, его вид выводится из компонентов кита (например, `aria-invalid` у поля shadcn).

## Чтение рамки

1. Открыть файл: `code -r "design/<продукт>.pen"`.
2. Список экранов: рамки верхнего уровня без рамок библиотек, черновики помечены.
   ```js
   Get((n,c)=>{c.skipChildren();if(n.type==="frame"&&!n.id.includes(":"))Print(n.id,"|",n.name,"|",n.name.startsWith("_")?"черновик":"экран")})
   ```
   У рамок подключённых библиотек в id есть `:` (`H:…`). По этому префиксу видно, какой кит подключён.
3. Поддерево рамки:
   ```js
   Print(Get("<id>",{depth:4}))
   ```
   - Глубже `depth` дети приходят как `"..."`.
   - `resolveVariables: true` даёт вычисленные значения вместо `$переменных`.
   - `resolveInstances: true` раскрывает экземпляры компонентов, их id становятся путями `экземпляр/ребёнок`.

   Большую рамку удобнее печатать компактно, обходя дерево в JS:
   ```js
   const w=(n,d)=>{Print("  ".repeat(d)+[n.type,n.name,n.ref??"",n.content??""].join(" | "));for(const c of Array.isArray(n.children)?n.children:[])w(c,d+1)}
   w(Get("<id>",{depth:999}),0)
   ```
4. Посмотреть глазами: `TakeScreenshot(["<id>"])` прикладывает картинку к ответу. Это дорого — один раз на рамку. PNG для сверки делается через `Export` (раздел «Сверка»).
5. Переменные (цвета, радиусы, шрифты): `Print(GetVariables())`.
6. Справка по раскладке в виде HTML: `Export(["<id>"],"html-tailwind","<корень>/.scratch/<продукт>/<Экран>.html")`. Tailwind и шрифты Google там подключаются по сети, в макет как есть не идёт (`design/motion/docs/pen-frame-export.md`).

Что вынести из рамки:
- раскладку: направление, `gap`, `padding`, ширины;
- тексты — буква в букву;
- цвета — через переменные кита;
- шрифты;
- какие компоненты кита стоят (`ref` → компонент библиотеки);
- имена слоёв для `element`;
- отдельно нарисованные состояния.

## Экран в React

- Каждая рамка верхнего уровня → `src/screens/<Экран>.tsx` и запись в `src/screens/index.ts` с `id` = имя рамки ([runtime.md](runtime.md), «Экран»).
- Собирать из настоящих компонентов кита. Для shadcn — `npx shadcn@latest add <имя>` в `<продукт>/mockup`, компоненты ложатся в `src/components/ui/`. Экземпляр библиотеки в рамке сопоставляется компоненту кода по имени и варианту. Какой компонент в какую роль — таблица в [runtime.md](runtime.md), «Соглашения по компонентам кита».
- Раскладка — классами Tailwind по значениям рамки, у любого кита. Компоненты кита — со своими пропсами (вариант, размер), как в его документации. Тексты — как в рамке. Цвета — токенами темы кита (`bg-primary`, `text-muted-foreground`), а не hex, если в рамке не стоит свой цвет.
- Подвижные места оборачиваются в `R.*`, `element` = имя слоя.
- Состояния — раздел «Нарисованные состояния».
- **Обводка.** В pen.dev обводка не занимает места в раскладке, а выгрузка html-tailwind рисует её CSS-рамкой (`border`). В React переводить так: вместо `border` ставить `ring-1 ring-inset` или `shadow-[inset_0_0_0_1px_var(--color-border)]` (одна сторона — `shadow-[inset_0_-1px_0_var(--color-border)]`); либо оставить `border` и вычесть его из padding/размера. Иначе всё ниже сдвинется на толщину рамки.
- **Иконки lucide.** Набор lucide в pen.dev старше `lucide-react`: часть имён и рисунков отличается. Имена проверять в `lucide-react`, при отсутствии брать ближайшую иконку (или собрать из узлов старой через `createLucideIcon`).
- Логики ровно столько, чтобы показать состояния и переходы: ввод, ошибка, успех, загрузка, навигация между ключевыми экранами. Бэкенда и настоящих данных нет.
- Ссылки между экранами (`href="#/<id>"`) — только там, где навигация есть в pen.dev. Если неясно, спросить. Ради ссылок можно править и другие экраны.
- Библиотечный компонент целиком — только если в ките нет аналога (например, OTP), перекрашенный токенами кита.

## Адаптеры китов

Адаптер — это запись в `ADAPTERS` (`design/motion/scripts/adapters.mjs`) плюс правила из этого раздела: установка React-библиотеки, тема и встроенные анимации кита. Внутри одного продукта — один кит. Разрешённые сочетания записываются в адаптер явно.

### Адаптер shadcn (готов)

- **Шаблон уже на shadcn**, `install` ничего не делает.
  - `components.json`: стиль `radix-nova`, базовый цвет `neutral`, иконки `lucide`. Инициализация шла командой `npx shadcn@latest init -t vite -b radix -p nova -y --no-monorepo`.
  - Шрифт Geist (`@fontsource-variable/geist`, `"Geist Variable"`, как в ките shadcn-obra) встраивается в итоговый HTML.
  - `src/index.css` подключает `tw-animate-css` и `shadcn/tailwind.css`. Тема — CSS-переменные в `:root` и `.dark`.
- **Кит в pen.dev** — `design/libraries/shadcn-obra/shadcn-obra.lib.pen` (shadcn Obra). Перед первой сверкой сравнить цвета, `--radius` и шрифт кита (`GetVariables()`) с `src/index.css`. Отличаются — перенести значения кита в `:root`.
- **Где shadcn (nova) отличается от кита Obra в pen.dev** и что уже исправлено в шаблоне:
  - Button: `border-transparent` + `bg-clip-padding` дают заливку 30 px вместо 32 и ширину на 2 px больше. В шаблоне убран `bg-clip-padding`, у размера `default` стоит `px-[9px]` (9 + 1 px рамки = 10 px до текста, как в pen).
  - Card: ring рисуется снаружи коробки, в pen обводка внутри. В шаблоне добавлен `ring-inset`.
  - Badge (в шаблоне нет): после `npx shadcn@latest add badge` в `badge.tsx` заменить `px-2` на `px-[7px]` и `font-medium` на `font-semibold` (7 + 1 px рамки = 8 px до текста, вес как в pen).
  - Остальные компоненты сверять так же: измерять края в PNG и править класс в `src/components/ui/`, а не на каждом экране.
- **Компоненты**: `npx shadcn@latest add <имя>`, например `button card input input-otp dialog`. Зависимости смотреть заранее: `npx shadcn view <имя>`.
- **Встроенные анимации.**
  - **Оверлеи** — dialog, alert-dialog, sheet, popover, dropdown-menu, select, tooltip, hover-card и другие. Анимируются классами `tw-animate-css`. В shadcn 4.23 (`radix-nova`) они выглядят так: `data-open:animate-in data-open:fade-in-0 data-open:zoom-in-95 data-closed:animate-out data-closed:fade-out-0 data-closed:zoom-out-95 duration-100`. В старых версиях: `data-[state=open]:animate-in …`.

    **Если у активного стиля задана роль `overlay`, эти классы с компонента снимаются**, чтобы на одном элементе не спорили две системы движения, а Content получает `forceMount`. Разметка экрана и реализация роли — [runtime.md](runtime.md), «Оверлеи». Пока кандидатов несколько, в `src/components/ui/<имя>.tsx` это делается по условию:
    ```tsx
    const { styles, activeId } = useMotionRuntime() // из '@/motion/runtime'
    const styled = Boolean(styles[activeId]?.roles.overlay)
    // <…Primitive.Content forceMount={styled || undefined}
    //   className={cn(!styled && 'data-open:animate-in data-open:fade-in-0 … data-closed:animate-out …', '…остальные классы')} />
    ```
    После фиксации условие убрать. У выбранного стиля есть `overlay` — классы удалить совсем, `forceMount` оставить. Нет — вернуть как было.

    Если у стиля роли `overlay` нет, оверлей двигается анимацией кита. В паспорте строка `overlay` так и пишется: «Анимация кита: fade и zoom 95%, 100 мс», лицензия — «как у кита». Иначе спецификация соврёт.
  - **Портал.** Оверлеи Radix рендерятся в `document.body`, вне корневого `div`. Но `MotionRoot` дублирует `data-motion-style`, `data-motion-reduced` и `--m-*` на `<html>`, поэтому селекторы `style.css` с префиксом стиля и переменные до порталов доходят. Контекст React через портал тоже проходит, `useMotionRuntime()` работает.
  - **Закрытие.** Radix убирает закрытый контент после окончания его CSS-анимации, а без неё — сразу. Поэтому при заданной роли у Content стоит `forceMount`, а реализация роли держит его в `AnimatePresence` по `active`. Соглашение ещё не проверено на настоящем оверлее → [runtime.md](runtime.md), «Оверлеи».
  - **Кнопка**: `transition-all` и `active:not-aria-[haspopup]:translate-y-px`. Стиль, который двигает transform, сужает `transition-property` и снимает `translate` в своём `style.css` ([runtime.md](runtime.md), «Стиль»).
  - **Другие переходы** (`transition-all`, `transition-[color,box-shadow]`). Если роль анимирует то же свойство через Motion, сузить переход в `style.css`.
- **Разрешённые сочетания**: пока нет.

### Адаптер HeroUI — адаптера ещё нет

Раздел появится вместе с адаптером, когда процедура «Новый кит» будет пройдена для HeroUI. Пока `new-product --kit heroui` откажет. Заранее известно из спецификации: HeroUI сам построен на framer-motion, и у его компонентов свои анимации. Стиль должен либо управлять ими, либо отключать их (`disableAnimation` или `motionProps` — по документации через Context7).

## Новый кит

Процедура доработки адаптера для любого кита из pen.dev: Chakra, Tremor, Bootstrap 5, SDS, SnowUI или нового. Перед началом сказать пользователю, что адаптера нет, и получить согласие. Код скриптов дорабатывается с тестом (`superpowers:test-driven-development`).

**Адаптер готов**, когда тест `newProduct({ kit })` зелёный и один экран на этом ките проходит smoke и `compare`.

**Киты не на Tailwind** (Chakra, Bootstrap 5 и подобные):
- Tailwind остаётся в шаблоне для раскладки, а кит подключается своим провайдером.
- Файлы shadcn из шаблона (`src/components/ui/`, `components.json`) не удалять, если они не мешают.
- Конфликты — сброс стилей, слои CSS, одинаковые имена переменных — записать в адаптер.

1. **Найти React-пакет кита и его установку через Context7**:
   - `mcp__plugin_context7_context7__resolve-library-id` → `mcp__plugin_context7_context7__query-docs`;
   - что узнать: установка в Vite + React 19, провайдер темы, как кит уживается с Tailwind 4 из шаблона (сброс стилей, слои CSS).

   **Если React-кода нет, как у SnowUI**, адаптер собирает вид на shadcn + Tailwind по макету или по выгрузке HTML из pen.dev (`Export([id],"html-tailwind",…)`, `design/motion/docs/pen-frame-export.md`). Тогда в адаптер записывается, какой компонент кита каким компонентом shadcn передаётся.
2. **Добавить запись в `ADAPTERS`** (`design/motion/scripts/adapters.mjs`): `<кит>: { async install(mockupDir) { … } }`.
   - `new-product` вызывает `install` после копирования шаблона и до `npm install`.
   - Что делает `install`: дописывает зависимости в `mockupDir/package.json`; ставит провайдер темы в `src/main.tsx` или `src/App.tsx`; настраивает Tailwind или CSS в `src/index.css`. Лучше без сети, чтобы тест оставался быстрым.
   - Если `install` бросает ошибку, `new-product` удаляет папку продукта.
   - Разрешённые сочетания с другими китами — здесь же, явно.
3. **Перенести переменные кита из `.lib.pen`** (цвета, радиусы, шрифты) в тему кода:
   - открыть `code -r "design/libraries/<файл>.lib.pen"`, затем `Print(GetVariables())` — там и темы (`themes`);
   - значения записать в тему провайдера кита или в CSS-переменные `src/index.css`;
   - шрифт — пакетом `@fontsource…`, чтобы итоговый HTML работал без сети (`smoke › offline single file` ловит внешние запросы).
4. **Составить список встроенных анимаций кита**: какие компоненты двигаются сами (оверлеи, табы, переключатели, аккордеон, рябь…) и чем это отключается (свойство, класс, CSS, провайдер).

   Правило: **если роль задана стилем, своя анимация компонента отключается**. Если не задана, движение кита остаётся и так и описывается в паспорте.
5. **Тест `newProduct({ kit: '<кит>' })`** в `design/motion/scripts/__tests__/product.test.mjs`:
   - сначала тест: в `mockup/package.json` есть пакет кита, `motion.json.kit === '<кит>'`. Он падает с «Адаптера для кита "<кит>" ещё нет»;
   - потом запись адаптера, тест проходит;
   - поправить проверку `expect(Object.keys(ADAPTERS)).toEqual(['shadcn'])`;
   - запуск: `cd design/motion && npm test`.
6. **Один экран на этом ките, `smoke` e2e и `compare`.** Это и есть первый прогон на настоящем продукте — том, ради которого делается адаптер:
   - продукта ещё нет — `new-product <продукт> --kit <кит>` и `npm install`. Отдельный пустой продукт для проверки не создавать;
   - ⏸ пользователь подключает `.lib.pen` к `design/<продукт>.pen`. Если библиотека уже подключена, шаг пропустить;
   - рамка с компонентами, у которых есть встроенные анимации, и экран в React;
   - `npx playwright test` и `npm run compare`;
   - вручную проверить, что компоненты двигаются только по стилю, без двойного движения.
7. **Записать адаптер в этот раздел**: подраздел «Адаптер <кит>». В нём пакет и установка, провайдер и тема, откуда взяты переменные, встроенные анимации и как они отключаются, разрешённые сочетания, найденные ловушки. Если процедура оказалась неполной, поправить и её.

## Сверка с pen.dev

1. **PNG рамки** — по `design/motion/docs/pen-frame-export.md`:
   - `mcp__pencil__execute` с `Export([...],"png","…/compare/pen/_raw",{scale:1})`;
   - переименовать в `<продукт>/mockup/compare/pen/<Экран>.png` (`/` в имени состояния → `--`);
   - масштаб всегда `{scale:1}`;
   - рамка без заливки выгружается прозрачной и сверяется как белая. Если фон экрана не белый, задать рамке заливку;
   - ⏸ ручная выгрузка — только если MCP недоступен.
2. **Сверка** (из `<продукт>/mockup`):
   ```bash
   npm run compare -- <Экран> compare/pen/<Экран>.png [styleId]
   ```
   - Что делает команда:
     - собирает макет (`vite build`);
     - открывает `dist/index.html#/<Экран>` (с `?style=<id>`, если он задан и есть в `candidates`) в Chromium размером с PNG;
     - включает reduced motion и прячет панель;
     - ждёт шрифты и 2,5 с, делает снимок.
   - Пишет `compare/diff/<Экран>.mockup.png` и `compare/diff/<Экран>.diff.png`, печатает `Расхождение: N% — …`.
   - Ошибки: такого экрана нет (печатается список экранов), размеры не совпали.
3. **Остаток от глифов.** pen.dev рисует часть глифов на 1–3 % шире, чем Chromium с тем же файлом шрифта. Остаток сверки около 2 % и редкие другие переносы строк ожидаемы, это рендер pen.dev. Не подгонять `<br>` и `letter-spacing` под него.
