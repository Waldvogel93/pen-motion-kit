# Флоу по шагам с командами

Где запускать:
- `node design/motion/scripts/…` — из корня репозитория. Пути в аргументах (папка стиля для `lint-style` и другие) — тоже от корня;
- `npm` и `npx` макета — из `<продукт>/mockup`;
- `npm test` скриптов — из `design/motion`.

## Содержание
1. Создать продукт
2. Бриф и референсы
3. Экраны в pen.dev

## 1. Создать продукт

```bash
node design/motion/scripts/new-product.mjs <продукт> --kit shadcn
cd <продукт>/mockup && npm install
```

- Имя продукта: латиница, цифры, `-` и `_`, без путей (`/^[a-z0-9][a-z0-9-_]*$/i`). Без `--kit` берётся `shadcn`.
- Кит без адаптера — ошибка `Адаптера для кита "<кит>" ещё нет — сначала доработай адаптер …`. Это процедура «Новый кит» в [pen-to-react.md](pen-to-react.md).
- Папка продукта уже есть — ошибка `Продукт "<продукт>" уже существует`.
- Что создаётся:
  - `brief.md` — заготовка с разделами «Продукт», «Аудитория», «Сценарии», «Настроение», «Референсы»;
  - `motion.json` = `{"kit":"shadcn","style":null,"candidates":[],"overrides":[]}`;
  - пустая `docs/`;
  - `mockup/` — копия шаблона без фикстур, экрана `Example`, стилей `fixture-*`, `e2e/runtime.spec.ts` и `e2e/compare.spec.ts`, с пустым списком экранов.
- Если что-то упало, скрипт сам удаляет недостроенную папку продукта, поэтому команду можно просто повторить.
- Пока нет ни экрана, ни кандидата, панель макета пишет `Нет ни одного стиля: candidates пуст, а style не задан`, а на странице стоит «Экранов пока нет: добавьте их в src/screens/index.ts.». Это нормально.
- Если Playwright не находит браузер: `npx playwright install chromium`. Браузеры лежат в `.scratch/ms-playwright`, это задаёт `env` в `.claude/settings.local.json` (его создаёт установка, см. `INSTALL.md`).

## 2. Бриф и референсы

- **Полный проход**: записать в `brief.md` продукт, аудиторию, сценарии и настроение со слов пользователя.
- **Готовые экраны без брифа**: сначала прочитать рамки ([pen-to-react.md](pen-to-react.md)). Потом коротко спросить о продукте и настроении, если по макету этого не понять. Потом заполнить `brief.md`.
- Найти экраны-референсы в Screenrove по сценариям и посмотреть лучшие → [styles.md](styles.md), шаг 1.
- Снять движение с 2–4 референсов (сайты пользователя и живые страницы экранов Screenrove, не `signed-in`) командой `capture-motion` → [styles.md](styles.md), шаг 2. Показать пользователю «Сигнатурные приёмы» каждой записи со ссылкой на сайт.
- По стилю этих экранов и по брифу найти приёмы движения в библиотеке анимаций Screenrove → [styles.md](styles.md), шаг 3. Показать пользователю ссылки на демо (`url` и `demoUrl` записи), чтобы направление было видно заранее.
- ⏸ Пользователь может добавить свои референсы движения: сайт, видео, приложение. Записать их в «Референсы» брифа; сайт снять (шаг 2 [styles.md](styles.md)).

## 3. Экраны в pen.dev

Процесс уже существует и здесь не меняется.

- Макет — `design/<продукт>.pen`, прямо в `design/`. Pencil MCP создать файл не умеет: скопировать любой новый документ pen.dev (`~/.pencil/documents/<uuid>/pencil-new.pen`, в Windows `%USERPROFILE%\.pencil\documents\…`) в `design/<продукт>.pen` и открыть `code -r "design/<продукт>.pen"`.
- ⏸ Пользователь подключает библиотеку кита: Libraries → «+» у Imported Libraries → `design/libraries/…lib.pen`. Ждать подтверждения.
- Экраны собираются из компонентов кита по инструкциям `mcp__pencil__read_skill`. Имена рамок и слоёв — по правилам из [pen-to-react.md](pen-to-react.md).
- PNG рамок для сверки — в `<продукт>/mockup/compare/pen/` по `design/motion/docs/pen-frame-export.md`.

## 4. Кандидаты

Подбор и правила набора — в [styles.md](styles.md).

```bash
# новый кандидат — из заготовки, сразу в продукт
cp -r design/motion/styles/_template <продукт>/mockup/src/motion/styles/<id>
node design/motion/scripts/lint-style.mjs <продукт>/mockup/src/motion/styles/<id>

# готовый стиль из коллекции — копия в продукт и id в candidates
node design/motion/scripts/add-style.mjs <продукт> <id>
```

- `add-style` работает только со стилями из `design/motion/styles/`. Новые кандидаты вписываются в `candidates` в `motion.json` вручную.
- Порядок в `candidates` — это порядок кнопок в панели. Первый кандидат открывается по умолчанию.
- Новые кандидаты в коллекцию не кладутся. Туда попадает только выбранный стиль, при фиксации.

## 5. Первый ключевой экран: сверка, тесты, превью

Стиль выбирается один раз на 1–2 ключевых экранах. Второй нужен, только если это принципиально другая зона (вход, основной экран, дашборды). Экраны с теми же элементами отдельно не согласуются: после выбора они идут шагом 7.

1. **Какие экраны.** Те, что назвал пользователь. Если не назвал — главный экран из брифа (плюс второй из другой зоны, если есть). Если и так неясно — спросить.
2. **Собрать** `src/screens/<Экран>.tsx` и запись в `src/screens/index.ts` → [pen-to-react.md](pen-to-react.md), [runtime.md](runtime.md). Компоненты кита — `npx shadcn@latest add <имя>`.
3. **Сверить с рамкой** в каждом кандидате:
   ```bash
   npm run compare -- <Экран> compare/pen/<Экран>.png <id-кандидата>
   ```
   Как читать результат — [pen-to-react.md](pen-to-react.md), «Сверка».
4. **Тесты:**
   ```bash
   npx vitest run
   npx playwright test
   ```
   - `smoke.spec.ts` обходит каждый экран (кроме `_…`) в каждом кандидате и ждёт пустой список проблем в панели и ни одной ошибки в консоли. Без единого экрана smoke падает: «в макете нет ни одного экрана».
   - Второй тест собирает `dist/index.html` и открывает его без сети.
5. **Превью:**
   ```bash
   npm run dev
   ```
   - Запускать в фоне (`run_in_background`). Vite печатает адрес, обычно `http://localhost:5173/`.
   - Дать ссылку на экран: `http://localhost:5173/#/<Экран>`. Конкретный кандидат открывается так: `/?style=<id>#/<Экран>`, параметр стоит до `#`.
   - Смотреть можно в Simple Browser VS Code или в обычном браузере.
   - В панели макета есть переключатель кандидатов, их паспорта и ссылки на референсы, «Проиграть появление» и «Уменьшить движение».
   - После правки `motion.json` перезагрузить страницу: при горячей замене активный стиль заново не выбирается.
   - Остановить сервер — только его PID.

## 6. Выбор стиля и фиксация

1. ⏸ Пользователь выбирает стиль — один раз для всего продукта. Дальше все экраны собираются шагом 7.
2. Записать выбор в `motion.json`: `"style": "<id>"`.
3. Зафиксировать:
   ```bash
   node design/motion/scripts/fix-style.mjs <продукт>
   ```
   - Выбранного стиля нет в `<продукт>/mockup/src/motion/styles/` — ошибка, ничего не удаляется. Копия в коллекции макетом не подхватывается.
   - Остаются выбранный стиль и стили, на которые ссылаются `overrides`. Остальные папки кандидатов удаляются. Папки с `_` в начале имени не трогаются.
   - Если выбранного стиля нет в коллекции и `lint-style` для него чист, стиль копируется в `design/motion/styles/<id>/`. Если lint нашёл проблемы, они печатаются и перенос не происходит. Тогда поправить паспорт и запустить `fix-style` ещё раз.
   - `candidates` становится `[style]`.
   - Вывод: `Удалено кандидатов: …` и `Стиль перенесён в design/motion/styles` (или `Стиль в коллекцию не переносился`).
4. После фиксации переключателя стилей в панели нет. В итоговой сборке нет панели и нет экранов, чьи id начинаются с `_`.

## 7. Новый экран при выбранном стиле — сводный чек-лист

Это путь по умолчанию для каждого следующего экрана: без кандидатов, досок и согласования. Принципиально другая зона (вход, кабинет, дашборды) собирается так же, пользователю отдаётся ссылка на результат, а не варианты.

Стиль зафиксирован: переключателя и кандидатов нет, `?style=` не нужен.

1. **Прочитать рамку** `<Экран>` в `design/<продукт>.pen` → [pen-to-react.md](pen-to-react.md), «Чтение рамки». Отметить нарисованные состояния `<Экран> / …`.
2. **Добавить компоненты кита**, которых ещё нет в `src/components/ui/`:
   ```bash
   npx shadcn@latest add <имя> [<имя> …]
   ```
3. **Собрать экран** `src/screens/<Экран>.tsx` с обёртками `R.*` по таблице «компонент кита → роль» → [runtime.md](runtime.md), «Соглашения по компонентам кита».
4. **Зарегистрировать** его в `src/screens/index.ts`: `{ id: '<Экран>', title: '…', component: <Экран> }`.
5. **Ссылки между экранами** (`href="#/<id>"`) — только там, где навигация есть в pen.dev. Если неясно, спросить. Ради ссылок можно править и другие экраны.
6. **Выгрузить PNG только этой рамки** (`mcp__pencil__execute`, файл открыт во вкладке):
   ```js
   const s=Get((n,c)=>{c.skipChildren();return n.type==="frame"&&!n.id.includes(":")&&n.name==="<Экран>"?n.id:undefined})
   Export(s,"png","<корень>/<продукт>/mockup/compare/pen/_raw",{scale:1})
   Print("MAP",s[0])
   ```
   Затем переименовать по id из строки `MAP`:
   ```bash
   mv "<продукт>/mockup/compare/pen/_raw/<id>.png" "<продукт>/mockup/compare/pen/<Экран>.png" && rmdir "<продукт>/mockup/compare/pen/_raw"
   ```
   Для рамки состояния `/` в имени файла заменяется на `--`: `Settings / confirm` → `Settings--confirm.png`.
7. **Сверить:**
   ```bash
   npm run compare -- <Экран> compare/pen/<Экран>.png
   ```
   Нарисованные состояния сверяются отдельными экранами → [pen-to-react.md](pen-to-react.md), «Нарисованные состояния».
8. **Тесты:** `npx vitest run` и `npx playwright test`.
9. **Ссылка** на `npm run dev`: `http://localhost:5173/#/<Экран>`.
10. **Новая роль.** Если экрану нужна роль, которой у стиля нет (в паспорте «Без анимации»):
    - дописать её в `<продукт>/mockup/src/motion/styles/<id>/style.tsx` в характере стиля, на тех же токенах;
    - параметры новой роли взять из записи референса выбранного стиля, если роль в ней есть; в паспорте «Источник» соответственно («снято с <домен>» или «без референса») → [styles.md](styles.md), шаг 2;
    - обновить строку роли в паспорте, затем `node design/motion/scripts/lint-style.mjs <продукт>/mockup/src/motion/styles/<id>`;
    - обновить копию в коллекции (команда в шаге 9). Если токены стиля подстраивались только под этот продукт, перед перезаписью коллекции спросить;
    - коротко сказать пользователю, что добавлено.
11. **Сдача** — если пользователь просит: `npm run build` и `motion-spec`, раздел «Фиксация» пропустить, стиль уже зафиксирован → [handoff.md](handoff.md). ⏸ Пользователь смотрит HTML.

## 8. Точечная правка

Делается только по явной просьбе пользователя («какие анимации подойдут для …», «покажи варианты для …»). Claude сам доску вариантов не предлагает и после фиксации стиля рутинным шагом не делает.

Доска вариантов описана в [runtime.md](runtime.md), «Доска вариантов».

1. **Варианты:**
   - **стиль не выбран** — у каждого кандидата есть эта роль; на доске `use: "<кандидат>:<роль>"` (или `"<кандидат>:<роль>/<вариант>"`);
   - **стиль выбран** — варианты в `variants['<роль>/<вариант>']` выбранного стиля; на доске `use: "<стиль>:<роль>/<вариант>"`;
   - **вариант из другого стиля** (только по просьбе пользователя) — `add-style <продукт> <другой>`. Он попадёт в `candidates`; после выбора снова запустить `fix-style`: он вернёт `candidates = [style]`, оставит стиль-источник правки и удалит остальное.
2. ⏸ **Пользователь выбирает вариант.** Пока `style: null`, выбор ведёт по одной из двух дорог:
   - **«Беру этот»** — выбран вариант стиля S, значит выбран стиль S. Записать `"style": "S"`. Если выбран вариант (`S:otp/<вариант>`), а не основная роль стиля, добавить и правку из пункта 3. Затем `fix-style` (шаг 6);
   - **«Только для этого места»** — стиль продукта всё равно нужен, спросить, какой. Правку записать как `S:otp` или `S:otp/<вариант>` (пункт 3). Потом `style` = выбранный стиль и `fix-style`: он сохранит S как источник правки.
3. **Записать правку** в `motion.json`:
   ```json
   "overrides": [
     { "screen": "Login", "element": "OTP", "role": "otp", "use": "<стиль>:otp/<вариант>", "note": "луч вокруг активной ячейки" }
   ]
   ```
   - `screen` — id экрана, то есть имя рамки;
   - `element` — имя слоя в pen.dev, ровно как в `element` у обёртки на экране;
   - `role` — роль этой обёртки (`R.Otp` → `otp`);
   - `use` — `стиль:роль` или `стиль:роль/вариант`.
4. **Паспорт стиля-источника**: строка варианта в таблицу «Роли» (`` `otp/<вариант>` ``) с параметрами, источником и лицензией. Затем `lint-style`.
5. Если правка совпала с выбранным стилем продукта (`<style>:otp` при `style` = `<style>`), она ничего не меняет, и её можно убрать.
6. Битая ссылка в `use` или элемент, которого нет на экране, видны в списке проблем панели.

## 9. Правки

**Визуальная правка** делается в pen.dev: пользователем или Claude через Pencil MCP.
1. Изменить рамку в `.pen`.
2. Заново выгрузить PNG этой рамки (шаг 7, пункт 6).
3. Пересобрать компонент экрана (раскладка, тексты, цвета), сохранив обёртки `R.*` и их `element`.
4. `npm run compare`.

`motion.json` при этом не трогается. Если в pen.dev переименовали слой, панель предупредит: `Элемент "…" из overrides[i] не найден на экране "…" — переименован в pen.dev?`. Тогда поправить `element` и на экране, и в `overrides` и сказать пользователю.

**Словесная правка движения** («пружина мягче», «тряска слабее», «каскад медленнее»):
- **для всего продукта** — меняются `tokens.json` стиля продукта (`<продукт>/mockup/src/motion/styles/<id>/tokens.json`) или код роли в его `style.tsx`;
- **для одного места** — точечная правка: вариант роли и запись в `overrides`, как в шаге 8;
- **непонятно, что из двух** — спросить: «Для всего продукта или только для <место>?».

| Слова | Что менять |
|---|---|
| быстрее, медленнее | `duration.fast` / `base` / `slow` |
| каскад медленнее, быстрее | `stagger` |
| пружина мягче, резче, меньше отскока | `spring.snappy` / `spring.soft`: мягче — ниже `stiffness`; меньше отскока — выше `damping` |
| сдвиг меньше, больше | `distance` |
| меньше размытия | `blur` |
| тряска слабее | амплитуда в коде роли (`style.tsx`) |

После правки:
- числа в столбце «Параметры» паспорта должны совпадать с `tokens.json`. Спецификация берёт токены из `tokens.json`, а роли из паспорта;
- `lint-style`;
- коротко сказать пользователю, что изменилось.

Правки токенов под продукт в коллекцию сами не уходят. Если пользователь хочет сохранить их как отдельный стиль, нужен новый id.

Варианты и новые роли пополняют стиль. После `lint-style` обновить копию в коллекции, но только если версия продукта не содержит подстройки токенов под продукт (иначе сначала спросить):

```bash
rm -rf design/motion/styles/<id> && cp -r <продукт>/mockup/src/motion/styles/<id> design/motion/styles/<id>
```
