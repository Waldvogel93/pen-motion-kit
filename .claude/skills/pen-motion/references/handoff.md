# Сдача: фиксация, один HTML, спецификация движения

Последний шаг флоу ([flow.md](flow.md), шаг 10). Согласованный HTML — эталон для разработки: вот так интерфейс выглядит и вот так двигается.

Если стиль уже зафиксирован (новый экран при выбранном стиле), раздел 1 пропустить и начать с раздела 2.

## 1. Фиксация

Сдают только зафиксированный продукт. Проверить:
- `style` в `motion.json` задан;
- `node design/motion/scripts/fix-style.mjs <продукт>` выполнен ([flow.md](flow.md), шаг 6);
- в `mockup/src/motion/styles/` остались только выбранный стиль и стили, на которые ссылаются `overrides`;
- `candidates` = `[style]`;
- выбранный стиль лежит в коллекции `design/motion/styles/<id>/`.

Если после фиксации в стиль добавлялись варианты или роли, обновить и копию в коллекции ([flow.md](flow.md), шаг 9).
## 2. Сборка в один HTML

Перед сборкой (и при входе 4 тоже):
- паспорт выбранного стиля проходит `lint-style`;
- числа в «Ролях» совпадают с `tokens.json` и кодом;
- у каждой строки есть источник и лицензия;
- в «Источниках и установке» есть все команды.

Из `<продукт>/mockup`:

```bash
npm run build
npx playwright test
```

- `npm run build` — это `tsc -b && vite build`. Результат — один самодостаточный `dist/index.html`: скрипты, стили и шрифт встроены (`vite-plugin-singlefile`). Проверка формы сборки — `npm run test:build`.
- `smoke › offline single file` собирает макет, открывает `dist/index.html` с диска с заблокированной сетью и ждёт ноль внешних запросов и ни одной ошибки консоли.
- В итоговой сборке с выбранным стилем нет панели и нет экранов с `_` (доски вариантов, черновики).
- Открыть `dist/index.html` двойным кликом (или по пути `<корень>/<продукт>/mockup/dist/index.html`) и убедиться в этом глазами.
- `dist/` в git не попадает. Нужен файл в репозитории — по просьбе пользователя скопировать его в `<продукт>/docs/`.

## 3. Спецификация движения

```bash
node design/motion/scripts/motion-spec.mjs <продукт>
```

Пишет `<продукт>/docs/motion-spec.md` из паспорта выбранного стиля, его `tokens.json` и `overrides`. Без выбранного стиля — ошибка «Стиль не выбран». Разделы:

| Раздел | Откуда |
|---|---|
| Стиль | название и «Характер» паспорта (там же отступления от правил Screenrove) |
| Токены | таблица из `tokens.json`: мс и px с единицами, кривые как `cubic-bezier(…)`, пружины |
| Изменения вида в покое, Роли, Reduced motion | разделы паспорта дословно |
| Точечные правки | таблица «Экран, Элемент, Реализация, Комментарий» и строка роли из паспорта стиля-источника |
| Источники и установка | раздел паспорта, плюс разделы стилей, на которые ссылаются правки |
| Где смотреть в коде | `mockup/src/motion/styles/<id>/style.tsx`, `mockup/src/screens/` |

Прочитать результат целиком: у каждой роли и правки точные параметры, у каждого источника — команда установки и лицензия. Если чего-то нет, поправить паспорт и запустить `motion-spec` ещё раз. Сам `motion-spec.md` руками не правят: он перезаписывается.

## 4. Что отдать разработке

- `<продукт>/mockup/dist/index.html` — эталон вида и движения, открывается двойным кликом.
- `<продукт>/docs/motion-spec.md` — токены, роли с точными параметрами, правки, источники с командами и лицензиями, reduced motion.
- Код стиля как справку: `<продукт>/mockup/src/motion/styles/<id>/` (`style.tsx`, `tokens.json`, `style.css`) и экраны `mockup/src/screens/`.
- Короткий список зависимостей: кит продукта, `motion` и дополнительные компоненты из «Источников и установки». Компоненты кита не заменялись библиотечными, поэтому разработчик получает свой кит, Motion и этот список.

⏸ Пользователь смотрит итоговый HTML и спецификацию. Правки — по [flow.md](flow.md), шаг 9. После правок сборку и `motion-spec` повторить.

## 5. Git

Коммитить, когда просит пользователь. В `git add` — только пути продукта и стиля, `git add -A` и `git add .` не использовать:

```bash
git add design/<продукт>.pen <продукт>/brief.md <продукт>/motion.json <продукт>/mockup <продукт>/docs design/motion/styles/<id>
```

`node_modules/`, `dist/`, `compare/`, `test-results/` исключены `.gitignore` макета. Никогда не коммитить `.superpowers/` и `.scratch/`. Новый кит в `design/libraries/` — только если его лицензия разрешает передачу, с записью в `design/libraries/CREDITS.md`.
