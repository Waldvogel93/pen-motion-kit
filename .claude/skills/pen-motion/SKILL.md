# Живой макет pen.dev со стилями движения

Холст pen.dev статичный. Этот скилл превращает его экраны в **живой макет** — React-проект продукта, где движение задаёт **стиль движения на весь продукт**. Стиль работает как цветовая тема, только для движения: одно решение задаёт, как ведут себя кнопки, поля, карточки, появление экрана и остальное. Пользователь смотрит свой экран в 2–3 стилях, подобранных под продукт, переключает их на лету и выбирает стиль целиком. Следующие экраны сразу собираются в нём. В конце получается один HTML-файл, который открывается двойным кликом, и `<продукт>/docs/motion-spec.md` для разработки.

Механика уже есть в репозитории. Скилл ведёт по ней, заново её писать не нужно.

| Что | Где |
|---|---|
| Макет продукта | `design/<продукт>.pen` — прямо в `design/`, иначе он не видит киты |
| Киты pen.dev | `design/libraries/**/*.lib.pen` |
| Коллекция стилей и заготовка `_template` | `design/motion/styles/` |
| Шаблон живого макета: движок, панель, e2e, сверка | `design/motion/template/` |
| Скрипты | `design/motion/scripts/`: `new-product`, `add-style`, `fix-style`, `motion-spec`, `lint-style`, `capture-motion`; адаптеры китов — `adapters.mjs` |
| Снятые референсы | `design/motion/captures/<slug>/`: `record.md`, `capture.json`, `media/` (медиа не в git) |
| Продукт | `<продукт>/brief.md`, `<продукт>/motion.json`, `<продукт>/mockup/`, `<продукт>/docs/motion-spec.md` |

**Где запускать команды:**
- `node design/motion/scripts/…` — из корня репозитория. Пути в аргументах, в том числе папка стиля для `lint-style`, — тоже от корня;
- `npm` и `npx` макета — из `<продукт>/mockup`;
- `npm test` скриптов — из `design/motion`;
- в вызовах Pencil MCP (`Export` и другие) пути абсолютные: `<корень>` — абсолютный путь к корню репозитория (`pwd` в нём), с прямыми слешами.

## Сначала проверь кит

Проектировать в pen.dev можно на любом ките из `design/libraries/`. В живом макете кит работает, только если у него есть **адаптер** — запись в `ADAPTERS` в `design/motion/scripts/adapters.mjs`. Какие адаптеры есть, смотри в этом файле (на 31.10.2026 — только `shadcn`).

Кит продукта записан в `kit` в `<продукт>/motion.json`. Если продукта ещё нет, кит видно по библиотеке, подключённой к `.pen` ([pen-to-react.md](references/pen-to-react.md), «Чтение рамки»). Если не видно, спроси.

**Если у кита нет адаптера**, макет не начинай и кит другим не подменяй: сравнение с pen.dev не сойдётся, а разработка получит чужой кит. Сразу скажи пользователю, например: «Экраны на Chakra оживить можно, но адаптера живого макета для Chakra ещё нет. Предлагаю сначала сделать его по процедуре „Новый кит“, потом продолжу с продуктом». После согласия выполни раздел «Новый кит» в [pen-to-react.md](references/pen-to-react.md) и только потом переходи ко входу. `new-product` без адаптера всё равно откажет.

Внутри одного продукта — один кит. Сочетание китов (например, shadcn + Tremor для графиков) допустимо, только если адаптер явно его разрешает.

## Выбери вход

Посмотри `<продукт>/motion.json` (`style` равен `null` или id стиля) и есть ли экраны в `.pen`.

| Ситуация | Вход |
|---|---|
| Спрашивают про **одно место или элемент** («какие анимации для OTP», «покажи варианты для кнопки») | 3. Точечный запрос — даже если экраны есть и стиль не выбран |
| Есть бриф или идея, экранов в pen.dev ещё нет | 1. Полный проход |
| Просят оживить экраны целиком, стиль не выбран или продукта ещё нет | 2. Оживить готовый экран |
| Стиль выбран (`style` не `null`), нужен ещё экран | 4. Новый экран при выбранном стиле |

Строки проверяются сверху вниз: запрос про одно место — всегда вход 3.

### 1. Полный проход

- [ ] Кит и адаптер — раздел выше.
- [ ] Создать продукт: `new-product`, затем `npm install` → [flow.md](references/flow.md), шаг 1.
- [ ] Бриф в `<продукт>/brief.md` со слов пользователя → [flow.md](references/flow.md), шаг 2.
- [ ] Референсы экранов в Screenrove, движение, снятое с 2–4 референсов (`capture-motion`), и находки в библиотеке со ссылками на демо → [styles.md](references/styles.md), шаги 1–3.
- [ ] Экраны в `design/<продукт>.pen` из компонентов кита → [flow.md](references/flow.md), шаг 3. ⏸ Библиотеку кита подключает пользователь.
- [ ] Дальше — вход 2, начиная с кандидатов.

### 2. Оживить готовый экран

- [ ] Кит и адаптер. Если продукта нет — `new-product` → [flow.md](references/flow.md), шаг 1.
- [ ] Прочитать рамки через Pencil MCP → [pen-to-react.md](references/pen-to-react.md). Брифа нет — после чтения коротко спросить о продукте и настроении (если по макету непонятно), заполнить `brief.md`.
- [ ] 2–3 кандидата под продукт → [styles.md](references/styles.md).
- [ ] Стиль выбирается **один раз** на 1–2 ключевых экранах: главный экран, плюс второй, только если это принципиально другая зона (вход, лендинг, дашборды). В React на них собираются все кандидаты, сверка, тесты, ссылка на `npm run dev` → [flow.md](references/flow.md), шаг 5.
- [ ] ⏸ Пользователь выбирает стиль → `style` в `motion.json` и `fix-style` → [flow.md](references/flow.md), шаг 6.
- [ ] Все остальные экраны сразу собираются в выбранном стиле (вход 4), без кандидатов и досок.
- [ ] Сдача → [handoff.md](references/handoff.md).

### 3. Точечный запрос

- [ ] Варианты одного места делаются **только по явной просьбе** («какие анимации подойдут для …», «покажи варианты для …»). Доску вариантов Claude сам не предлагает и не делает рутинным шагом после фиксации стиля.
- [ ] Продукта нет — сначала кит и `new-product`, как во входе 2.
- [ ] **Стиль не выбран** (`style: null`):
  - 2–3 кандидата, подобранные под продукт → [styles.md](references/styles.md). Это полноценные стили и первый шаг к выбору стиля продукта. Реализуются только роли, которые есть на экране, остальные — «Без анимации»;
  - собрать и **настоящий экран** с этим элементом (например `Login`), и **доску** `_variants/<место>`. Smoke требует хотя бы один экран без `_`;
  - зависимости: компонент кита (`npx shadcn@latest add input-otp`), декоративные слои — по [sources.md](references/sources.md).
- [ ] **Стиль выбран**: только если пользователь прямо просит варианты этого места, 2–3 варианта внутри стиля — `variants['<роль>/<вариант>']`. Вариант из другого стиля — только если пользователь просит выделить это место.
- [ ] Доска `VariantsBoard` (для OTP — с `states`), устройство роли → [runtime.md](references/runtime.md), «Доска вариантов» и «Соглашения по компонентам кита». Наброски `design/motion/sketches/*.html` — только образец формата, доска его уже повторяет.
- [ ] В ответе — ссылки на референсы каждого варианта (страница записи Screenrove и её демо; снятый сайт и его `record.md`) и на доску в `npm run dev`.
- [ ] ⏸ Пользователь выбирает. При `style: null` выбор варианта стиля S — это выбор стиля S. Если пользователь говорит «только для этого места», стиль продукта всё равно нужен — спросить. Как записать оба случая → [flow.md](references/flow.md), шаг 8.

### 4. Новый экран при выбранном стиле

- [ ] Стиль зафиксирован, поэтому переключателя и кандидатов нет. Экран собирается сразу в этом стиле, **без кандидатов, досок и согласования**. Это путь по умолчанию для каждого следующего экрана.
- [ ] Принципиально другая зона (вход, кабинет, дашборды) — тоже собирается в стиле, пользователю показывается результат (ссылка), а не варианты. Недостающие роли дописываются в характере стиля → [flow.md](references/flow.md), шаг 7, п. 10.
- [ ] Сводный чек-лист с командами → [flow.md](references/flow.md), шаг 7: рамка → компоненты кита → экран с `R.*` → `src/screens/index.ts` → PNG только этой рамки → `compare` → тесты → ссылка на `npm run dev`.
- [ ] Нужна роль, которой у стиля нет, — дописать её в характере стиля → [flow.md](references/flow.md), шаг 7. Референсы не снимаются; параметры берутся из записи референса выбранного стиля, если роль есть в ней → [styles.md](references/styles.md), шаг 2.
- [ ] Просят сдачу — `npm run build` и `motion-spec`, фиксацию пропустить → [handoff.md](references/handoff.md).

## Где ждать пользователя ⏸

Здесь не решай за пользователя и не иди дальше, пока он не ответил.

1. **Подключить библиотеку кита в pen.dev**: Libraries → «+» у Imported Libraries → файл из `design/libraries/`. Агент этого сделать не может.
2. **Выбрать стиль** — после ссылки на `npm run dev`. До выбора `style` в `motion.json` остаётся `null`, а `fix-style` не запускается.
3. **Выбрать вариант** на доске `_variants/…` — только если пользователь сам попросил варианты места.
4. **Выгрузить PNG рамки** — только если `Export` через Pencil MCP не работает. Ручной способ описан в `design/motion/docs/pen-frame-export.md`.

Спросить также, когда:
- непонятно, какой экран ключевой ([flow.md](references/flow.md), шаг 5);
- непонятно, где в pen.dev навигация между экранами;
- словесная правка движения может быть и для всего продукта, и для одного места ([flow.md](references/flow.md), шаг 9).

## Правила

- **Движение объясняет**: откуда что взялось, что произошло после нажатия, что изменилось. Анимация ради анимации выглядит дёшево.
- **Правила движения Screenrove** действуют по умолчанию. Их снимок с числами лежит в [sources.md](references/sources.md). Отступить можно осознанно и с записью в паспорте стиля.
- **Стиль согласуется один раз и тиражируется; варианты мест — только по просьбе.**
- **Анимации не выдумываются**: снимаются с референсов (`capture-motion`) или берутся из библиотеки Screenrove; кандидат повторяет движение своего референса.
- **Кандидаты сначала подходят продукту, потом у каждого своя идея** (фирменный приём виден с первого взгляда; варианты одной идеи не считаются), оси темпа, упругости и силы — вторичная проверка. Для разных продуктов получаются разные наборы → [styles.md](references/styles.md).
- **Макет совпадает с рамкой pen.dev**: раскладка, отступы, шрифты, тексты, цвета. Расходиться можно только там, где паспорт стиля объявил изменения вида в покое.
- **Компоненты кита не заменяются библиотечными.** Motion оживляет настоящие компоненты кита. Из библиотек берутся приёмы, параметры и декоративные слои. Библиотечный компонент целиком ставится, только если в ките нет аналога, и перекрашивается токенами кита.
- **Источники только бесплатные.** Источник и лицензия каждого приёма записываются в паспорт → [sources.md](references/sources.md).
- **`.pen` — только через Pencil MCP**, никогда через Read или Grep. Файл должен быть открыт во вкладке (`code -r "<путь>"`) → [pen-to-react.md](references/pen-to-react.md).
- **Только веб.** Всё лежит внутри репозитория, временное — в `.scratch/`, глобально ничего не ставится.
- **Процессы не убивать по имени образа.** `taskkill /IM node.exe` убьёт все node, в том числе чужие. Останавливать только процесс, который запустил сам. Сервер для e2e Playwright поднимает и гасит сам.
- **Движок продукта не править мимоходом.** `mockup/src/motion/` — копия шаблона. Если движок нужно доработать, сначала доработать `design/motion/template/` с тестом (`superpowers:test-driven-development`), потом перенести в продукт и сказать об этом пользователю.
- **Git**: коммитить, когда просит пользователь, и только свои пути → [handoff.md](references/handoff.md).
